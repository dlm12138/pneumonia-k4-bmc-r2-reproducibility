# Per-program execution and prerequisite manual

This guide describes the retained programs and their prerequisites; private inputs are not included. Follow full_process_steps.tsv rather than alphabetical ordering. Real-data runs must write outside this repository. Direct execution of source-history code is guarded. The I/O contracts describe required relative paths and private input layouts; configure legally held inputs first.

## Environment and workflow conventions

DATA_ROOT identifies a private project/input tree; OUTPUT_ROOT identifies a dedicated private output tree. ANALYSIS_INPUT selects the final corrected complete frame. FEATURE_MATRIX supplies the original hourly candidate matrix for the clinical summary helper. DUCKDB selects an installed DuckDB CLI. CLEANING_SCHEMA supplies ONLY the actual historical vital/valid_min/valid_max columns for the selected landmark matrix function, not fitted means or mixture parameters. The additional SOURCE_* keys replace actual former absolute paths. Their basenames and usage are in source_resource_requirements.tsv. Their private values are never published.

Install requirements.txt for current Python calculations; optional historical direct dependencies are in requirements_historical.txt. R and DuckDB are separate runtimes. Read data_access.md before accessing the raw sources. No credentials belong in this directory.

## Commands for current downstream stages

Set the named environment variables to your own authorised private directories before running. These commands describe conditional execution, not a completed public-only replay. The oxygen-dependent workflows require completed strict-input assembly and the entire current oxygen replacement, including lower-coverage additions. Use program_arguments.tsv for exact source-defined flags.

```sh
python code/tests_synthetic.py --output-root "$OUTPUT_ROOT/synthetic" --duckdb duckdb
python code/tests_source_history.py --output-root "$OUTPUT_ROOT/source_synthetic"
python code/workflows/01_pneumonia_specificity.py --project "$DATA_ROOT" --output "$OUTPUT_ROOT" --raw "$DATA_ROOT/raw"
python code/workflows/03_primary_and_fixed_sensitivities.py
python code/workflows/04_oxygen_affected_associations.py
python code/workflows/05_fixed_fold_prediction.py --project "$DATA_ROOT" --output "$OUTPUT_ROOT"
```

These are separate stages, not a shell script to run blindly. Check all input contracts, validation scaffolds and original relative subdirectories first. Workflows 06–13 have additional parameter/reference/event/site prerequisites; their flags and dependencies are enumerated below. Neither raw database credentials nor the public package supplies the withheld model or original fold files.

## Safe source-history inspection and conditional execution

Inspect original scientific functions and source I/O without importing whole source-history programs: some original programs read data at module level. Do not import them to list functions. The function catalogue was generated by parsing, not by executing their pipeline.

```sh
python code/run_source_reference.py --execute-source-reference source_history/raw/01_pneumonia_identification.py
```

Options for the guarded launcher MUST precede the source positional argument. Additional original program arguments follow that source argument. The launcher requires DATA_ROOT/OUTPUT_ROOT and configured SOURCE_* keys. For selected-function modules, call the documented original functions explicitly from a private driver after configuring their paths; loading the module alone does not reconstruct a cohort.

Historical model derivation/finalisation additionally requires --allow-historical-fit to prevent accidental execution. Current application analyses require the original frozen K4; a new fit cannot replace it. Original private module layout is needed where dynamic_module_references.tsv specifies module files. source_module_aliases.tsv shows the corresponding retained source; file renaming must not change the scientific function body.
