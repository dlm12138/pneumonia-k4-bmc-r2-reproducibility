# Execution order

Read the scope limitations and input contracts before running. Public-code inspection and synthetic checking do not require database access; real-data execution requires independently approved access and correct private inputs. No stage downloads credentials or transmits data.

1. Inspect `results/`, `results_catalog.tsv` and provenance. Install `requirements.txt`; DuckDB CLI and R packages are separate requirements, not MySQL.
2. Run `code/tests_synthetic.py` with an output directory outside the repository. Do not confuse synthetic passing checks with actual study replication.
3. Prepare legally held historical candidates and required flow/diagnosis inputs. `workflows/01_pneumonia_specificity.py --project "$DATA_ROOT" --output "$OUTPUT_ROOT" --raw "$DATA_ROOT/raw"` implements the actual stricter gate on those candidates. It does not recreate the entire historical candidate search.
4. Inspect `core/raw_vitals.py` for the actual four-vital cleaning/aggregation implementation. Restrict the returned item mapping to the four phenotype variables before calling the scanner. Pulse oxygen must be processed with the new source-specific SQL, not this historical general item matcher.
5. Render the appropriate oxygen/support SQL with `code/render_sql.py`, providing raw-directory and selected-key paths. Execute privately using DuckDB. Merge hourly sum/count then call `core.oxygen.aggregate_hourly_spo2`; replace the whole oxygen source and include lower-coverage additions. SQL includes patient linkage fields and outputs remain restricted.
6. Exact K4 assignment is conditional on authorised possession of the original numerical assets. Use `core.locked_k4.assign_locked_k4`, original feature order and original mapping; do not re-fit or re-standardise. If parameters are unavailable, stop this branch. Downstream analysis with already authorised original labels is a separate branch.
7. Once the corrected compiled frame exists, `workflows/03_primary_and_fixed_sensitivities.py` uses `ANALYSIS_INPUT` and `OUTPUT_ROOT` to call the original functions for primary, conventional means, HR/RR, APACHE, comorbidity and definition sensitivities. It dispatches these calculations without implementing a separate estimator; estimator code and source specifications are documented.
8. `workflows/04_oxygen_affected_associations.py` uses `DATA_ROOT` and `OUTPUT_ROOT` for the actual current oxygen/full adjustment, complete HR/RR, hospital and ordinary/aligned composite calculations. It requires the private event inputs and current aggregate scaffold lookup. Preserve non-estimable statuses; do not replace separated unpenalised models with penalised fits.
9. `workflows/05_fixed_fold_prediction.py --project "$DATA_ROOT" --output "$OUTPUT_ROOT"` fits five models on the original saved folds. The imported original function fixes L2/C=1.0/lbfgs/max_iter=2000; tolerance is the original default 1e-4. Bootstrap is paired on existing out-of-fold predictions. Reproduction requires the original folds and fixed settings, not regenerated folds or retuned parameters.
10. `workflows/06_oxygen_coverage.py` requires original frozen assets plus private ≥24-dimension inputs and current primary output. Then, conditional on additional historical private inputs, `07_domain_early_posterior.py`, `08_time_order.py`, `09_hospital_transport.py`, and `10_selection_weighting.py` implement the corresponding actual sensitivities. Use the original module inputs/flags shown in `workflow_inputs.tsv`. Do not assume this is a dependency-complete raw-to-paper executable pipeline.
11. R workflows 11–13 implement actual eICU/MIMIC competing-risk and hospital hierarchical analyses. Their source comments and input tables specify the needed evidence, design and aggregate checks. The eICU R workflow receives the public package root as its second argument solely to locate the retained reconstruct function. Other project-relative inputs, where present, are private prerequisites.
12. Compare output N/events, phenotype labels, OR/SHR/RD, interval type and model identifiers against the corresponding aggregate table. Source paths must not be placed into a release. Repeating modelling to obtain preferable results is not part of reproduction.

If required source files are unavailable, record the branch as unavailable/partial; do not manufacture replacement data or claim a new fit reproduces the frozen model. Patient-level outputs must remain private; only aggregate outputs that have passed a disclosure review are eligible for public sharing.
